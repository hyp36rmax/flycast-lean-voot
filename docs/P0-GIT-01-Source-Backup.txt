PROJECT OT SOURCE BACKUP POLICY — P0-GIT-01

Private backup only. Public release and visibility changes require separate approval.
Keep private Experience implementation and Flycast GPL runtime in separate repositories.
Do development on feature branches. Make focused commits and versioned milestone tags.
Associate physical UAT evidence with both full commit IDs, build inputs and executable hashes.
Never alter Golden References. Never label later work as accepted without acceptance evidence.
Verify uploaded branch and annotated tag object IDs using git ls-remote after every backup.
Never force-push or push all branches/tags from the retained history bundles.
Retain license/copyright files and corresponding runtime source with distributed runtime builds.
No CI, feature changes or public release are part of this milestone.

Recovery: clone the PRIVATE remote, then checkout the accepted tag below. If remote access is
unavailable, git clone the corresponding verified checkpoint.bundle from P0-GIT-01 instead.
The original *-history.bundle files preserve earlier history; they do not contain uncommitted
working files. The working-tree-backup directories and vendor-source archive preserve those.
Keep the Golden reference, working-tree backups, dependency archive and protected assets on
separate protected backup storage as well. A second folder on the same disk is not disaster recovery.

Toolchain observed: Windows x64; Git 2.54.0.windows.1; .NET SDK 10.0.401;
CMake 4.4.3; Visual Studio 18 2026; Windows SDK 10.0.26100.0.
Do all builds in fresh writable directories; never build inside a Golden Reference.
